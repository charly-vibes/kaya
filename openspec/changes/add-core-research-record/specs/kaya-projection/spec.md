## ADDED Requirements

### Requirement: Managed block grammar

Documents SHALL mix generated and authored content through two block forms: `<!-- kaya:begin generated:<name> -->` … `<!-- kaya:end generated:<name> -->` for compiler-owned sections and `<!-- kaya:authored -->` … `<!-- kaya:end authored -->` for human-maintained sections. The compiler SHALL regenerate only the content inside generated blocks and SHALL byte-preserve everything outside them, including authored blocks, uncategorized prose, and foreign managed blocks (for example other tools').

#### Scenario: Authored bytes preserved

- **WHEN** a projection regenerates a document whose authored block contains
  interpretation prose
- **THEN** every byte of the authored block and of surrounding uncategorized
  prose is identical before and after regeneration

#### Scenario: Foreign managed blocks untouched

- **WHEN** a document also contains another tool's managed block (for
  example a wai block)
- **THEN** the compiler leaves it byte-identical — kaya owns only kaya
  markers

### Requirement: Deterministic generation

A projection SHALL generate byte-identical sections across runs and machines for identical ledger, graph, and template state — no timestamps of generation, no map iteration order, no locale-dependent formatting inside generated blocks.

#### Scenario: Same inputs, same bytes

- **WHEN** the same dossier is built twice from identical state
- **THEN** the generated sections are byte-identical between the runs

### Requirement: Incremental rebuild

A rebuild SHALL recompute only projections whose inputs changed since the
last build, determined from the event frontier; projections whose inputs
are unchanged SHALL keep their previous bytes without recomputation.

#### Scenario: Unaffected projection untouched

- **WHEN** a new run event arrives and a rebuild executes
- **THEN** the experiment report for the affected experiment is recomputed
  and the research index and unrelated reports keep their prior bytes

### Requirement: Stale-authored flagging

When an authored block's cited evidence changes after its last acknowledgment, the compiler SHALL report the block as stale in the build summary — naming the changed evidence ids — and SHALL NOT alter the block's bytes. Acknowledgment is a human act recorded as an event.

#### Scenario: Evidence change flags the block

- **WHEN** a run event changes counts that an authored interpretation cites
- **THEN** the build summary reports the authored block as stale, naming
  both the block and the changed evidence ids, and the block's bytes are
  unchanged

### Requirement: Property coverage mirror

Every property row in the layer sidecar SHALL be verified by exactly one
dedicated scenario.

#### Scenario: authored_preserved

- **WHEN** regeneration runs on a document with authored and foreign blocks
- **THEN** non-generated bytes are identical before and after
- **VERIFIES** [[kaya.projection.authored_byte_preserved]]

#### Scenario: deterministic_bytes

- **WHEN** identical state is built twice
- **THEN** generated sections are byte-identical
- **VERIFIES** [[kaya.projection.generated_deterministic]]

#### Scenario: incremental_minimality

- **WHEN** one event lands and a rebuild runs
- **THEN** only frontier-affected projections are recomputed
- **VERIFIES** [[kaya.projection.incremental_scope]]

#### Scenario: stale_detection

- **WHEN** cited evidence changes under an authored block
- **THEN** the summary flags staleness naming evidence ids, bytes untouched
- **VERIFIES** [[kaya.projection.stale_flagging]]

#### Scenario: sourcemap_completeness

- **WHEN** a generated block is inspected
- **THEN** each fact in it traces to named event ids
- **VERIFIES** [[kaya.projection.source_map]]

#### Scenario: grammar_checked

- **WHEN** a document contains an unterminated generated block
- **THEN** the build refuses with a labeled error naming the block
- **VERIFIES** [[kaya.projection.managed_grammar]]
