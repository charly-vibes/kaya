kaya is a living record of exploration: it turns the artifacts a project already
produces into continuously generated, human-owned documentation. Documentation
drifts because it is written separately from the work that makes it true; kaya
captures events, decisions, evidence and artifacts from the tools used during
development (wai, dont, whisper/turu, specodelic, git, test runners) and
compiles them into projections, so the record grows out of the work instead of
stopping it.

Use kaya when a repository's documentation must stay grounded in what actually
happened — decisions taken, experiments run, evidence collected — or when
onboarding, human or agent, should reconstruct *why* the software is the way it
is. Kaya is a consumer and integrator of those tools, never a replacement for
any of them: it assumes they already own their own authoritative records, so the
same fact is entered once and cited everywhere else.

Status: experimental · MVP-1 CLI implemented · long-form rationale in the
[motivation & design](../src/index.md) page.
