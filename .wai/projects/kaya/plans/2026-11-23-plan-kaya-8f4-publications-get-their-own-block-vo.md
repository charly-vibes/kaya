PLAN kaya-8f4: publications get their OWN block vocabulary and their own validator, applied where publication pages are planned.

DECISION (and why not the alternative): the ticket offers 'publications get their own block vocabulary and validator' or 'a documented exemption'. The evidence settles it: a documented exemption would bless a state where a page carries a stale, misspelled publication block and no gate notices - 'kaya publish' exited 0 and 'kaya check' reported drift [] on exactly that fixture. A vocabulary that is only described is not enforced. So: a publication page's managed block name is validated against the publication vocabulary at plan time, and an out-of-vocabulary name is a labeled refusal naming the block, before anything is written.

DESIRED BEHAVIOR:
- The publication vocabulary is publication.<tier>.<name> where <tier> is one of the three tier names and <name> is in that tier's closed vocabulary. The vocabulary is derived from the tier vocabularies that already exist (PRODUCTS, COLLECTIONS, PACKAGES) - no new list is invented, and no second copy of the eleven document kinds is added.
- A publication page whose generated block name is outside that vocabulary is REFUSED with a labeled error naming the block (the file is left untouched). This covers a misspelled tier ('publication.produkt.overview'), a name outside the tier's vocabulary ('publication.product.glossary' - a collection name under the product tier), and a documents-family block name ('orientation.research-map') appearing in a publication page.
- The research-document side is unchanged: validate_generated_blocks keeps refusing an out-of-vocabulary <family>.<kind> and a repeated name in a research document.
- The deployed specs state the publication block vocabulary explicitly, so the corpus says what the code enforces.

OUT OF SCOPE:
- No change to the eleven research document kinds or their vocabulary.
- No change to the document taxonomy or to how research documents are named.
- No new dependency and no new vocabulary list.
- Not a general block-name grammar change: the shared marker grammar (kaya:begin generated:) is unchanged; only which names a publication page may carry is pinned.
- Not a reclassification of publication pages as research documents: publication pages are published pages, not projected documents.

TEST CASES TO WRITE FIRST (red):
1. A publication page carrying a misspelled publication block is refused: the build fails with a labeled error naming the block and the file, and the page's bytes are unchanged.
2. A publication page carrying a documents-family block name is refused: the build fails naming the block.
3. A publication page carrying a valid publication block builds as today (regression guard): the existing publication tests must stay green.
4. The research side is unchanged: a research document with an out-of-vocabulary block is still refused by validate_generated_blocks (existing coverage, pinned by the run's other tests).
