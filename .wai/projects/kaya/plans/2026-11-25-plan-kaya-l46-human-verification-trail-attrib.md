# Plan — kaya-l46: human verification trail attributed and content-bearing

## Facts (verified in tree)

- `verification.record.reviewed` is written by `cmd_disposition`
  (src/commands/impact.rs:113-202): data = `{record, disposition}` (+`rationale`
  for waivers). Waivers bind `digest = impact::dependency_digest(record)`
  (impact.rs:655-663 lapse check); reviews bind nothing — a review cannot go
  stale in the record's own terms. Actor + verdict already exist: envelope
  `actor` = `human_actor(name)`, `disposition` field = the verdict. The real
  content gap is the digest, and the *visibility* gap: the impact gate renders
  the reviewed set as bare ids.
- The walk surface per ticket: "extend `kaya ir` or add a walk-through mode to
  acknowledge". `kaya ir` (src/commands/publication.rs:356) serializes
  `DocumentIr` (records + `RenderedBlock{name, body, provenance: Vec<String>}`
  from src/projection/ir.rs:39). Provenance ids are never resolved — eyeballing
  IDs is exactly the current state.

## Change (two seams)

### Seam 1 — `kaya ir --walk` (read-only walk-through, no write path)

New flag on `Ir` in the clap tree; `cmd_ir` gains a walk branch that emits, per
document and per rendered block: the block `body` (the generated bytes a human
checks), each provenance id resolved to its event summary (type, subject,
actor name+type, timestamp — from the same ledger events already loaded), and
the recorded human trail for the owning record: latest
`verification.record.reviewed` / `waived` / `acknowledged` per block or record
with actor, disposition (the verdict), the digest (seam 2), and `fresh` =
digest still equals `dependency_digest(record)`. Source-file-backed facts keep
their collector source path+bytes reference already present in the IR. JSON
envelope, same as `kaya ir`. No mutation, no projection writes.

### Seam 2 — reviewed events bind their evidence digest

`cmd_disposition`: `reviewed` data gains `digest` (same
`impact::dependency_digest(record)` waivers bind). Gate semantics unchanged —
waivers keep their lapse behavior; review staleness is surfaced by the
walk-through, not by the gate. Dedup comparison (`existing` search) compares
whole `data`, so a re-review after content change produces a distinct event —
the intended behavior, covered by an acceptance assertion.

## Red tests (tests/acceptance.rs patterns)

1. `reviewed_disposition_binds_evidence_digest` — record `reviewed` on a
   fixture record; event data carries `digest == dependency_digest(record)`;
   waiver path unchanged (rationale + digest still present).
2. `ir_walk_resolves_provenance_and_trail` — fixture ledger + docs/research
   with a reviewed record: walk output contains the block body text, the
   provenance ids resolved to actor+type, and the trail entry
   `{actor, disposition: "reviewed", digest, fresh: true}`; mutate the record's
   inputs (no re-review) → walk reports `fresh: false` for that trail.
3. Guard: plain `kaya ir` output (no flag) stays byte-shape-compatible with
   existing consumers (existing tests keep passing unchanged).

## Non-goals

- No gate-behavior change (reviews do not lapse in `kaya impact`).
- No new event types; no schema bump (SCHEMA_V0 data extension).
- No acknowledge changes — its equivalence/dedup stays as shipped.
